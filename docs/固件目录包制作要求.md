# 固件目录包（选择目录包…）制作与要求详解

> 适用软件：**BR23 学习机刷机助手**（Qt 版 v2.1+，单文件 exe）
> 适用场景：想在软件第 3 步用 **"选择目录包…"** 按钮，刷入自己（或他人）打包的杰理固件目录。
> 参考基准：exe 内置的 `bundled\msd_package\`（12 个文件），照着凑即可。

---

## 1. 背景：目录包走的是哪条刷机链路

软件有两条独立的刷机引擎：

| 引擎 | 触发按钮 | 适用对象 | 是否需要外部工具 |
|---|---|---|---|
| **isd_download 链路** | 选择测试固件 / 选择目录包… / 选择单文件包…(目录型) | 杰理标准固件目录包 / 单文件包 | 内置官方烧录器 `isd_download.exe` |
| **裸写引擎（raw）** | 选择原厂固件 / 选择单文件包…(1MB 裸镜像) | 1MB NOR 全片位级备份 | 不需要，进程内实现 |

**目录包 = isd_download.exe 的工作目录**。软件把烧录器的工作目录切到该文件夹、按固定参数模板调用它，所以目录包的内容必须满足杰理打包目录的规范。

软件第 3 步选中目录包后，会先在本地做一轮**静态校验**（不打扰设备），全部通过才显示 ✓ 并允许进入第 4 步。

---

## 2. 软件校验规则（显示 ✓ 的硬性条件）

校验逻辑（`analyze_dir`）检查以下内容：

### 2.1 必备文件（缺一个直接判 ✗）

| 文件 | 作用 | 缺失后果 |
|---|---|---|
| `isd_config.ini` | 烧录配置：flash 布局、升级方式、按键定义 | isd_download 无法确定写入布局 |
| `key.txt` | 烧录密钥（对应 `-key key.txt` 参数） | 报密钥相关错误 |
| `uboot.boot` | 引导镜像（写入 0x12000 指定位置） | 无引导可烧 |
| `app.bin` | 主固件（SDK 编译产物） | 无应用可烧 |

### 2.2 推荐文件（存在就自动追加到 `-res` 参数）

| 文件 | 作用 |
|---|---|
| `tone.cfg` | 提示音资源包 |
| `cfg_tool.bin` | 配置工具在线调试资源 |
| `eq_cfg_hw.bin` | EQ 硬件配置 |

### 2.3 烧录器位置

软件会在 **目录本身 → 上一级 → 上两级** 查找 `isd_download.exe`。
单文件 exe 版已内置烧录器，**用户无需自备**；只有当内置包检测失败时才需要外置。

### 2.4 isd_config.ini 关键字段检查（软件会读并警告）

- `DOWNLOAD_MODEL` —— **必须以 `usb` 开头**（见 §4.1）
- `RESET` —— 长按升级按键定义（见 §4.2）
- 解析时**只看激活行**：以 `#` 或 `;` 开头的注释行会被跳过（曾因 SERIAL 配置的注释行导致误报，现已修正）

## 3. 实际能刷成功还需要的"隐式"文件

静态校验不查、但 isd_download **运行时会打开**的文件。缺了会报
`打开文件br23loader.bin失败` 之类的错误（本项目实测踩过的坑）：

| 文件 | 用途 | 缺失现象 |
|---|---|---|
| `br23loader.bin` | 烧录前要灌进芯片 RAM 的下载 loader | **必失败**，最关键 |
| `font.bin` | 字库资源 | 打包/运行阶段失败 |
| `gbk2utf8.tab` | GBK→UTF8 编码表 | 同上 |
| `ota.bin` | OTA 升级信息（软件日志里打印 OTA UPDATE INFO 的来源） | 打包阶段失败 |
| `script.ver` | 版本脚本 | 打包阶段失败 |

> **结论：一个真正能用的目录包 = 4 必备 + 3 推荐 + 5 隐式 = 12 个文件。**

---

## 4. isd_config.ini 关键字段详解

### 4.1 `DOWNLOAD_MODEL`（最容易被改错）

```ini
DOWNLOAD_MODEL=usb            ; ✅ 正确：按 USB MSC（U盘）方式扫描设备
DOWNLOAD_MODEL=SERIAL         ; ❌ 错误：按串口(COM)扫描
```

- 设备进入下载模式后，在电脑上以 **U 盘（USB Mass Storage）** 形式出现（`BR23 UBOOT1.00`）。
- 如果 `DOWNLOAD_MODEL` 配成串口类，isd_download 会去扫 COM 口，**必然报
  `ERR_NODEVICE`（设备离线）**，且日志只会显示"only package the file"。
- 软件校验时会专门解析此字段并在非 usb 时给出 ⚠ 警告。

### 4.2 `RESET`（长按升级按键）

```ini
RESET=PB01_08_0               ; 长按 8 秒（PB01 按键）进入 TF 卡升级
```

本项目设备的按键约定是 **PB01 长按 8 秒**。若换其它设备型号，按对应硬件改。

### 4.3 FLASH 布局段

需与芯片实际 flash 匹配（本项目为 **1MB 内置 NOR，div8 布局**）：

```ini
FLASH_BIN_SIZE=0xe6000        ; 固件镜像总大小
; VM 区、BTIF 保留区等由 SDK 配置生成，不要手改
```

## 5. 烧录命令模板（软件自动拼装）

软件调用 isd_download.exe 的固定参数：

```
isd_download.exe -tonorflash -dev br23 -boot 0x12000 -div8 -wait 300
                 -uboot uboot.boot -app app.bin
                 -res tone.cfg cfg_tool.bin eq_cfg_hw.bin
                 -format all -key key.txt
```

| 参数 | 含义 | 对固件包的约束 |
|---|---|---|
| `-dev br23` | 芯片型号 BR23 | 固件必须是 AC695N（BR23）构建 |
| `-boot 0x12000` | 引导写入位置 | `uboot.boot` 必须是配套 BR23 引导 |
| `-div8` | 1MB NOR div8 布局 | flash 布局必须匹配 1MB 内置 NOR |
| `-format all` | 全片擦除（从 0x1000 起，引导区 0x0–0x1000 永不触碰） | — |
| `-wait 300` | 等待设备 30 秒 | 设备需先进入下载模式 |
| `-res …` | 资源文件列表 | §2.2 的文件存在才追加 |

**芯片匹配警告**：`-dev br23` 是写死的。如果把其它芯片（如 AC63x）的目录包喂进来，
静态校验能过、烧录也能完成，但**设备刷完开不了机**。
好在引导区永不擦除——用软件的 **"选择原厂固件"** 随时可救回。

## 6. 推荐的目录包清单（照抄内置包）

```
我的固件包\
├─ isd_config.ini      ← 关键：DOWNLOAD_MODEL=usb / RESET=PB01_08_0
├─ key.txt
├─ uboot.boot
├─ app.bin             ← SDK 编译主产物
├─ tone.cfg
├─ cfg_tool.bin
├─ eq_cfg_hw.bin
├─ br23loader.bin      ← 5 个隐式必需，缺一刷不了
├─ font.bin
├─ gbk2utf8.tab
├─ ota.bin
└─ script.ver
```

**从 SDK 构建产物凑包**：编译输出目录里拿 `app.bin`（及 `uboot.boot`），
其余配置/资源/隐式文件从任意一个**同芯片同布局**的既有完整包里复制
（它们是烧录器的工作文件，与 app 内容无关，除非你改了 UI 字库）。

## 7. 常见错误对照表

| 错误信息 / 现象 | 根因 | 处理 |
|---|---|---|
| 第 3 步显示"缺少必备文件: …" | §2.1 四文件缺漏 | 补齐后重新选择目录 |
| `打开文件br23loader.bin失败` | 缺隐式文件（§3） | 补 `br23loader.bin` 等 5 个文件 |
| `Device offline, only package the file`（退出码 -11） | ① 设备没进入下载模式 / 没枚举；② `DOWNLOAD_MODEL` 不是 usb | 先做第 2 步；检查 isd_config.ini |
| `ERR_NODEVICE` | 同上 ② | 同上 |
| 刷完设备开不了机 | 固件芯片/布局不匹配（§5 警告） | 用"选择原厂固件"还原 |
| 校验信息显示 ⚠ DOWNLOAD_MODEL 警告 | isd_config.ini 配置成串口扫描 | 改回 `DOWNLOAD_MODEL=usb` |
